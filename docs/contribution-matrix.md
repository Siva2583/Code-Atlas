# Team Checklist for Pull Requests and Collaboration

## Pull request checklist

- [ ] Create and work from your own branch.
- [ ] Keep the branch scoped to a single change or a very small related set of changes.
- [ ] Keep PRs small enough to review quickly and explain clearly.
- [ ] Add or update the relevant documentation for the change if the UI or workflow is affected.
- [ ] Check the diff before opening the PR and remove unrelated edits.
- [ ] Ask for review before merging.
- [ ] Do not merge your own PR without explicit review approval.
- [ ] Pull the latest branch state before starting new work.
- [ ] Rebase or update your branch when the target branch changes.
- [ ] Confirm the branch is clean and ready before requesting merge.

## Review expectations

- [ ] At least one peer review is required before merging.
- [ ] Review comments should be actionable and specific.
- [ ] The reviewer should validate both the functionality and the alignment to the project architecture.
- [ ] If a change affects the Fiori pages, confirm that the selection fields and filters still match the page definition.

## Working rhythm

- [ ] Start from the latest branch state.
- [ ] Keep commits focused and easy to understand.
- [ ] Keep large design decisions in a separate thread or documentation note instead of mixing them into a code PR.
- [ ] Finalize the PR only after the reviewer confirms the work is ready.

## Team rule

The team works in small, reviewable increments. This keeps the branch history clean, reduces merge conflicts, and makes the demo and governance workflow easier to review.
